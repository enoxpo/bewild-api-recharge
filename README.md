## 官方渠道怎么充值：规则比价格更值得先看

### 预充值 credits 的购买步骤

官方 API 按“预充值用量额度（usage credits）”计费，先买后用。流程三步：

1. 用 Admin 或 Billing 角色登录 Console；
2. 在 Billing 页面点 "Buy credits"；
3. 输入金额、确认，credits 立即到账。

credits 覆盖 API 调用、playground 和 Claude Code 的消耗，余额和用量明细都在同一个 Billing 页面看。

计费口径里有两条值得记住：只有成功的请求才扣费，失败的请求不收钱；但如果你在请求跑到一半时主动断开或超时，而这个请求原本大概率会成功，这一笔照样计费。跑长任务时别急着掐连接。

credits 耗尽后 API 会直接停掉，补了才能继续。怕中断可以开 auto-reload：在 Billing 页面设一个最低余额阈值和补充金额，低于阈值就自动充值。

### credits 一年过期，而且不可退款

这是官方充值最硬的限制：**购买的 credits 从购买日起一年过期，过期时间不能延长，所有购买不可退款**。过期记录会在 Billing 页面的 Invoice history 里显示。

另外，Claude Max 和 Team 订阅每月附带一部分 API 额度，把 Console 组织绑定到订阅计划后即可领取。消耗顺序是先扣每月赠送部分、再扣自己买的；赠送额度当月没用完就清零，而且不能用在 Claude Code 和 Claude 应用里——打算用它跑 Claude Code 的话要注意这点。

### 企业可以走月结

预充值不是唯一选项。通过销售团队开通月结（invoicing）安排后，可以先用后付：用量按月汇总，每月底收到 Stripe 发票，按标准按量价格结算。有正规采购流程、不想让工程师自己垫钱刷卡的公司，这条路更省事。

## 第三方充值平台为什么存在

第三方平台的模式不复杂：上游对接官方 API 或云平台（比如 AWS Bedrock），下游把接口转卖给开发者，赚差价，顺便解决支付和发票问题。

Apito 的页面上列过官方渠道的几个痛点：限流和排队、偶发的超时与 529 过载错误、“只能预付、没有月结”的付款方式。这些是平台自述，实际体验因人而异，但支付方式单一、发票缺失确实是官方渠道目前没有覆盖灵活的部分，对中国用户尤其明显。

选第三方平台，核心就看三件事：折扣力度、上游是否可靠、出了问题找不找得到人。

除了平台折扣，还有两个官方 API 自带的省钱开关：

- **Batch API（批量接口）**：大批量异步请求走 Message Batches API，官方直接打 5 折。批量分类、离线摘要这类不赶时间的任务很适合。

### 接入方式：基本只改一行 base_url

第三方平台基本都兼容官方 SDK。Kunavo 和 Apito 都支持两种接法：继续用 OpenAI SDK 指到它们的地址，或者用 Anthropic 原生 Messages API（/v1/messages），同一个 key 都能用。迁移成本就是改一行 base_url 的事。

CloseAI 的差异化在 Claude Code 适配：按它的页面说明，平台上所有模型（Claude、OpenAI、Gemini、Kimi、GLM 等）都原生支持 Claude Code，不需要第三方转换工具，也兼容 OpenClaw 这类个人助理项目。

数据安全方面，Apito 声称请求直连官方上游、不记录不缓存提示词和响应，密钥隔离、TLS 传输，并给出 99.8% 的可用性承诺。这些属于平台自述，介意数据的话，充值前值得把条款看一遍。

## 常见问题

### 充值后余额用不完会过期吗？

官方渠道会：购买的 credits 从购买日起一年过期，且不可退款。第三方平台规则不一，充值前看各自的条款。

### 第三方充值平台安全吗？

与其要结论，不如给判断方法：看它声明走什么上游（官方 API 或 Bedrock 级别较稳）、是否明示数据留存政策、是否只要求改 base_url 而不用大改代码。像 Apito 这种宣称零留存、只换接入地址的方式，风险相对可控；反过来，要求下载来路不明客户端的一律排除。

### 官方订阅送的 API 额度怎么领？

把 Console 组织绑定到 Max 或 Team 计划后领取，每月发放，先于购买的 credits 消耗，月底清零。注意它不能用于 Claude Code 和 Claude 应用。

### 失败的请求会扣钱吗？

官方规则是失败请求不计费；但客户端在请求中途断开或超时、而请求原本会成功时，这一笔仍会收取。
